## 2. 判定與重轉

> **這不是線／ways／cluster 遊戲**，判定核心是撲克牌型。骨架的 `evaluateLines()` 會整支換成 `evaluateHand()`，回傳同樣形狀（`{symbol, count, cells, score}`）讓演繹自動跟上。

### 2.1 得分判定

| 規則 | 來源 |
|---|---|
| 滾輪停止後，盤面組成標準撲克牌型即可得分 | `[§一般遊戲 D20]` |
| 若可同時組成多種得分牌型，**取牌型賠率最高者** | `[§一般遊戲 D57]` |
| 相同的牌型僅能得分一次，不會在同一局中重複計分 | `[§一般遊戲 D56]` → **判定粒度不明，見未知清單 #3** |
| WILD 可代替任意牌 | `[§一般遊戲 E61]` |

### 2.2 重轉（RESPIN）三種型態

`[§一般遊戲 D43:E51]`

| 條件 | 重轉行為 | 額外效果 |
|---|---|---|
| **成牌 2~4 張** | 鎖定並結算得分牌，其餘卡牌重轉 | 若重轉後鎖定的牌組成**更高賠率**的牌型，**必定再次觸發**重轉 `[E45]` |
| **成牌 5 張** | 結算得分牌後，**盤面所有卡牌**重轉 | **起始倍數加倍**（例 ×4 → ×8），效果持續至本局結束，進入下一局時重置 `[E47]` |
| **未得分且差一張成順子/同花** | **僅重轉缺少的那一張** `[E49]` | 僅未得分時觸發 `[E48]`；重轉若未中獎，**有機率再重轉一次**，次數無上限（待與 SERVER 討論上限）`[E50]`；**此重轉不新增功能卡** `[E51]` |

補充：重轉後，若以原有的牌與新出現的牌可組成**張數更多、或張數相同但牌型賠率更高**的得分牌型，即可再次贏分 `[§一般遊戲 D52]`。

### 2.3 回合迴圈

`[§一般遊戲 D41/D42/D53/D54/D55]`

```
局 (spin)
 └─ 回合 1 ── 得分 → 套用功能卡 → 累加本局總得分 → 觸發重轉 + 新增 1 張功能卡
    └─ 回合 2 ── …
       └─ … 直到某回合無牌型得分 → 結算本局總得分 → 局結束
```

- 每當組成得分牌型後 → 觸發重轉，**新增 1 張功能卡**至功能列，用於下一回合（最多累積 5 張）`[D41]`
- 每回合的功能卡與起始倍數在重轉期間持續保留，**直到該局結束** `[D42]`
- 每回合結算時，**由左至右依序**套用得分與倍數類型功能卡，計算回合得分並累加至本局總得分 `[D53]`
- 回合持續進行直到沒有牌型得分，該局結束 `[D55]`

⚠️ `[D54]`「回合結束後，得分與起始倍數重置，進入下一回合」與 `[D42]/[E47]`「起始倍數持續至本局結束」**互相矛盾** → 見未知清單 #2。

### 2.4 完整流程（企劃原文）

`[§一般遊戲 D83]`

```
滾輪停止 → 判斷是否有【轉換 WILD】功能卡 → （有）轉換盤面卡牌
→ 判斷得分牌型 → 依序套用得分、倍數類型功能卡 → 計算該回合得分
→ 累加至本局總得分 → 依牌型決定重轉方式並新增功能卡 → 重複以上流程
→ 無得分 → 結算總得分 → 結束本局
```

### 2.5 彩金計算

`[§一般遊戲 F95/F96]`、`[§FREE GAME F33/F34]`（NG 與 FG 相同）

```
得分   = 押注額 × 牌型賠率
彩金   = 得分（含功能卡加成） × 倍數
```

**狀態機順序修正**：企劃 `[§高倍得分層級設計 E5/F5]` 的兩段停留分別是「得分相乘**演繹前**停留」與「相乘演繹後、**跑分前**停留」，兩段都在跑分**之前**。原本的實作把 `POST_HOLD` 放在跑分之後（當時還沒有相乘演繹可夾），本次一併改正：

```
FEAT_APPLY → PRE_HOLD（演繹前停留＋鏡頭拉近）→ MULT_SLAM（相乘演繹：碰撞）
→ POST_HOLD（演繹後、跑分前停留）→ SCORE_RUN（跑分）→ SCORE_HOLD（分數停留 → 復原演繹）
```

**三個分數欄各自的規則**（使用者 2026-08-28 拍板，企劃沒寫）：

| 欄位 | 顯示什麼 | 跑不跑分 |
|---|---|---|
| 左上金色【得分 SCORE】 | **只有這一回合**的賠率贏分 ＋ 功能卡加上去的贏分（`scoreNow()`，含加得分／乘得分卡，**不含倍數**） | **不跑分**，也不會出現相乘後的分數。新的一局／新的一回合滾動時歸零 |
| 盤面中央（相乘結果，**跑分開始那一刻才出現**；達到大獎條件的回合不出，改由大獎畫面跑） | 上排小字 `得分 × 倍數`、下排大字＝最終得分 | **依平台慣例**（兩者都是大獎必跑）：星城＝贏分達 **10 倍以上或大獎**才跑分；H5＝**只有大獎**（BIG WIN 起，`FX.bigWinRatio`）才跑分。在【節奏】分頁最上方可切換，選擇會存進 localStorage 並寫進匯出的節奏表註記 |
| 下方公版 WIN | 連爆的**累積**分數 | **不跑分**。一回合的得分演繹跑完（`afterScore()`）才直接切換到新的累計值 |

實作位置：`scoreBoxValue()`／`slamResultValue()`／`CENTER_RUN_MODES`
（`centerRunEnabled()` 在 `startScoreRun()` 決定這一回合跑不跑）。
`SCORE_RUN` 這段時間軸長度不變（不跑分的級距同樣佔這段），它現在只驅動盤面中央的數字。

**面板出現＝開始跑**（使用者 2026-08-28）：中央得分面板不再於「相乘碰撞」時就跳出來停著等，
而是在 `SCORE_RUN` 進入時才建立（`startScoreRun()`），第 0 幀就已經在跑；
`MULT_SLAM`／`POST_HOLD` 期間畫面上沒有這張面板。大獎畫面同理，一出現就在跑分。

> ⚠️ **一項使用者指定、企劃沒寫的事**：企劃 `H47` 只寫到「兩欄碰撞」為止，**沒有寫相乘結果要顯示在哪裡**。

#### ⚠️ 兩個判斷，請你過目

1. **`RHYTHM_TYPE` 取 `百搭+連爆`。** Crescendo 有 WILD（百搭），得分後的重轉在節奏上

### 5.3 ⚠️ 實測發現（做完 demo 才浮現，需要企劃決定）

以下兩件事是**照企劃規則實作後跑 300 局 soak 才發現的**，企劃書裡沒有對應規定。

**① 起始倍數沒有上限 → 單局贏分會失控**

企劃 `[E47]`：「5 張牌全中 → 起始倍數加倍，效果持續至本局結束」，只給了「×4 → ×8」一個例子，**沒寫上限**。
照字面實作後，第一次 soak 的結果是 **RTP ≈ 1.35×10¹⁸ %**——因為一局內每次 5 張全中都加倍，配合乘得分 ×3、乘倍數 ×3 的功能卡，單局贏分可以指數爆炸。

→ 我加了 `[自設]` 的 `maxStartMult = 64`（一局內最多加倍 6 次）收斂，加上限後 soak 的 `maxMult` 穩定停在 64。
**這個上限請企劃拍板**：要幾倍、或改成「每局只能加倍一次」、或依 FG/NG 分開設定。調校面板【數值】分頁可直接拉。

**② 連爆太容易持續，命中率偏高**

加上限後的 300 局 soak（連跑 3 次，數字穩定）：

| 指標 | 實測 |
|---|---|
| HIT RATE | **79 ~ 83 %** |
| RTP | **66,000 ~ 82,000 %**（≈ 660 ~ 820 倍押注） |
| 平均單局長度 | 1,400 ~ 1,650 幀（≈ 23 ~ 27 秒） |
| 最長單局 | 約 53,000 幀（≈ 15 分鐘，達到 `maxRound=20` 上限） |
| 單局最大贏分 | 17,000 ~ 23,000 倍押注 |

原因是**「一對」在 1×5、每格獨立轉出、且同一張牌可重複出現的條件下太容易成立**（5 格全不同點數的機率只有約 45%），而一對就會鎖定 2 張、重轉 3 張、再湊到任何牌型就繼續連爆。收斂機制只有 `[D56]`「相同牌組僅能得分一次」。

**這不是 bug，是規則在這個盤面尺寸下的自然結果。** 兩個可能的方向（都要企劃決定，我不擅自改規則）：

1. **靠轉輪權重壓**：正式版權重由 SERVER 給，會大幅降低成牌率。demo 的權重是 `[自設]` 等權重，所以偏高。
2. **靠規則壓**：例如「一對不觸發重轉」、或把 `[D56]` 改成「同牌型種類一局只計一次」（我在確認規格時列為未知 #3，你選了「照具體牌組」）。

> **RTP 未校準這件事請務必記住**：轉輪權重是 `[自設]`，這個 RTP 數字**不能對外報告**。要粗調就動【數值】分頁的「全域賠率乘數」。
